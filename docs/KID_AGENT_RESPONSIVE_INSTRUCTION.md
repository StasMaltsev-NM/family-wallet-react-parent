# Инструкция для смежного агента (kids-app): полная адаптивность

## Контекст
Нужно довести верстку kids-приложения до стабильного mobile-first поведения на:
- старых Android (Samsung A-серии и аналогичные, узкие экраны),
- современных iPhone (включая Max-ширину),
- планшетах (iPad/Android tablets).

## Ограничения
- 1 задача = 1 ветка/1 PR.
- Не менять зависимости/версии без причины.
- Не переписывать архитектуру.
- Перед изменениями: `git status -sb` + backup ключевых файлов.

## План работ (выполнить по порядку)
1. Зафиксировать baseline:
   - собрать список проблемных экранов (главная, миссии, магазин, модалки),
   - снять скриншоты для viewport: `360x800`, `390x844`, `430x932`, `768x1024`, `1024x1366`.
2. Нормализовать layout-контейнеры:
   - убрать горизонтальный overflow,
   - проверить `safe-area` (`env(safe-area-inset-*)`),
   - ввести адаптивные `max-width` и `padding` через `clamp()`.
3. Привести шапку/свитчер профилей:
   - выравнивание по одной линии,
   - корректные размеры аватаров и кнопки `+` на всех ширинах,
   - горизонтальный скролл только внутри switcher, без скролла страницы вбок.
4. Привести модалки и формы:
   - поля и кнопки не выходят за экран,
   - скролл внутри модалки, а не страницы,
   - минимум `44px` tap-area для интерактивных элементов.
5. Привести карточки и списки:
   - fixed-пиксельные размеры заменить на fluid (`minmax`, `clamp`),
   - заголовки/числа не обрезаются,
   - skeleton/placeholder не ломают высоту карточек.
6. Проверить регрессии:
   - переключение тем,
   - загрузка при плохой сети,
   - ориентация portrait/landscape на планшете.
7. Дать отчет в PR:
   - какие файлы изменены,
   - какие viewport проверены,
   - какие баги закрыты (до/после).

## Технические критерии приемки
- Нет горизонтального скролла на `360px`.
- Все критичные кнопки/инпуты доступны без зума.
- Контент не обрезается на iPhone с вырезом и на Android с системными панелями.
- На планшетах интерфейс не «растянут», а центрирован и читабелен.
